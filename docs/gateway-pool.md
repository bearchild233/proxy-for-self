# 网关池插件

为降智账号所在的分组，按“账号 × 网关”轮换满血网关。降智信号在交付前拦截，用户只感到等待稍长。插件 UI 与策略可热更新；传输桥在 Rust 内核，首次启用需要内核与控制面升级。

## 术语

| 术语 | 含义 |
| --- | --- |
| 网关 | OpenAI 上游的接入节点，名称形如 `unified-142`。同一账号经不同网关访问，可能得到不同质量的服务。 |
| 池服务 | 外部网关池服务（默认 `https://pool.0102400.xyz`），维护各网关的路由 Cookie。`/gateways` 列出该成员可配对的网关、Cookie 剩余秒数与地区，`/cookie` 返回指定网关的 `__oailb` 与 `__cflb`。使用单独的池服务 Bearer，与 OpenAI 凭据无关。 |
| 池成员标识 | 向池服务声明的账号身份，默认自动生成 `gwpool-member:<上游账号 ID>/<上游用户 ID>`；管理员可在设置中覆盖。 |
| 组合 | 一个“账号 × 网关”。满血窗口、静置、学习和统计都以组合为单位。 |
| 打票模型 | 检测网关用的模型，默认 `gpt-6.1-sol`，reasoning low，输入 `hi`，无工具。 |
| 票 / 找票 | 票是某个模型在某个组合上的 state 与配套 Cookie。找票指用打票模型为账号寻找判定为 21 的网关。 |
| S0 | 携带池 Cookie 第一次访问上游（bootstrap）返回的 `x-codex-turn-state`。此后该模型在该组合上的请求固定带这份 state，不采用上游后续返回的新 state。 |
| bootstrap | 取 S0 的第一次请求，不做判定。 |
| 21 / 29 | 携带票重放后，在 HTTP 响应头判定：HTTP 200 且**不返回** `x-codex-turn-state` 为 21（满血）；HTTP 200 且**返回**该字段为 29（降智）。只看是否出现，不比较取值。这是约定的实验信号，不代表已验证回答质量。 |
| 拿票 | 窗口内来了其他模型的请求、该模型还没有票时，用该模型发一次 `hi` 取 state，拿到响应头即断开，不做第二轮判定。 |
| 检测失败 | 401、402、429、超时、网络错误、缺少配套材料，或 `__oailb` JWT 的 `host` 与指定网关不同。记录真实状态码，不记为 29。 |
| 满血窗口 | 组合从首次实际发送起的使用时间，默认 180 秒，所有模型共用。到期后开始准备下一组合，旧组合通常继续服务直到新组合验证通过；一轮结束或账号退出调度时停止接新请求。 |
| 静置 | 组合退役后禁止访问的时间，从最后一次实际访问上游结束时起算；期间任何真实访问都会重新计时。 |
| 退避档 / 学习起点 | 静置按初始档（默认 2h）→ ×2 → … → 上限（默认 24h）。复测仍为 29 或失败就升档。同一组合连续两轮在同一档恢复，以后从该档开始；恢复档不同则回到初始档。只记最后一档，不累计。 |
| lazy / continuous | 懒模式：没有请求时不找票，窗口到期后由新请求触发准备。持续模式：近期有流量的账号在空闲时也按窗口轮换。 |

## 行为

**范围**：只对设置中选定降智组的 OpenAI OAuth 账号生效。依据本次请求冻结目录中的实际成员身份判断，Key 直接指定多个账号或绑定多个分组都适用。同一账号属于多个组时只计一次，不能通过普通组绕过它的网关池参与开关。只有最终选中降智账号时才使用网关池传输；该传输依赖 HTTP 响应头，无法支持原生 WS。普通账号继续使用原传输与策略。

**Key 优先级与回退**：账号范围仍为指定账号和动态分组二选一。授权范围内可用的降智账号按共用队列优先于普通账号；所有降智账号额度耗尽、关闭参与、网关均冷却或暂不能获取窗口时，普通账号按该 Key 的轮转策略（未指定则继承全局）接手。候选可用性查询只读取已有目录与冷却状态，不触发探测。后续可重新选号的请求仍先检查降智账号，恢复后重新优先使用；已发送请求和严格续接保持现有安全边界。池控制面失败时，已确认身份的降智账号失败关闭，普通候选仍可回退；配置从未成功读取、无法确定分类时保守报错。只绑定降智账号的 Key（或固定账号）不会因账号暂时不在可调度名单里被提前拒绝：请求会进入网关池路由并得到具体原因。

**账号优先级**：“账号与网关”沿用账号管理的拖拽手柄，顺序与右侧“参与网关池”开关保存在插件 SQLite，所有 Key 共用。这是优先级，不是排队：每次请求在 Key 授权范围、模型权限、额度和并发限制内，选择优先级最靠前且可调度的账号，不要求排在队首；队列优先于会话亲和和权重。可调度指账号持有或正在准备窗口，或还有可检测的网关。同一 Key 内持有窗口的账号先继续服务，其余按优先级。开关仅控制网关池，不改全局账号启停。关闭后停止接新请求和后续探测，已经发送的请求正常排空。拖拽使用版本校验，自动移尾或其他管理操作先发生时，旧排序保存会被拒绝并刷新。

**一轮结束**：开始找票时固定该轮候选网关；真正访问过的网关退役时从待完成清单移除，全部结束后账号自动移到全局队尾。新一轮优先访问尚未完成的候选，仍遵守静置限制；未访问上游的失败不消耗一轮。额度首次确认耗尽时也移到队尾并暂停调度，重复上报不重复移动，额度恢复后保持队尾位置。配置改变候选范围时重新建立清单。持续模式采用相同队列，懒模式仍由请求触发。

**窗口按账号、一个 Key 一个账号**：满血窗口属于“账号×网关”。同一个 Key 同一时刻只用一个降智账号（持窗账号先用，其余按优先级），不同 Key 可各自使用自己的账号和窗口，不再整个分组只有一个窗口；两个 Key 选到同一账号时共用该账号的窗口。新窗口就绪时只退役同一账号的旧窗口，已发送的请求保留原归属。只绑定一个降智账号的 Key 没有退路：该账号有可检测网关就直接开窗口，一轮网关轮完后继续新一轮而不是让位。带 `previous_response_id` 的降智账号续接：原账号自己持窗，或 Key 里没有退路时留在原账号；窗口在同一 Key 的另一个账号上而原账号没有窗口时，由核心按已有规则使用已保存历史安全重放，缺少历史或存在不能迁移的工具状态时按原有规则返回错误，不直接把状态交给另一账号。

**失败原因**：网关池不能完成路由时，错误诊断带原因码和中文说明，管理员在“错误排查”里能直接看到：`queue_disabled`（账号在队列里停用）、`quota_exhausted`（额度耗尽）、`catalog_empty`（池目录或限定网关里没有可用网关）、`all_resting`（可用网关全部静置，写明最早恢复时间）、`wait_timeout`（等待超过请求期限，写明最后状态）、`no_probe_model_access`、`account_disabled`、`rate_limited`、`account_error`、`pool_disabled`、`member_unknown`、`control_plane_unavailable`、`yielded`。

**候选网关**：本轮尚未完成的候选优先，其内按既有 Cookie 有效期规则排序。默认跟随池服务。按账号的池成员标识查询 `/gateways`（缓存 60 秒），只用 `pair_ready` 的网关；网关从目录中消失就暂不作为候选，静置记录保留。设置中的“限定网关”非空时，只在其中且在目录中的网关里挑选；目录查询失败时退回限定列表或 5 分钟内的上一份目录。优先挑选 Cookie 剩余不少于一个窗口再加 60 秒的网关。

**池服务出口**：设置“池服务直连”默认开启，取目录与 Cookie 走服务器直连，避免账号代理无法访问池服务；打票、业务和额度请求始终走账号绑定的出口。

**Cookie 有效期**：票的到期时间取 Cookie JWT `exp` 与池服务 `valid_for_s` 的较早者，记在组合上。到期前 60 秒与窗口到期一样触发轮换；已过期的材料不会再被使用。

**找票**：取指定网关的池 Cookie → 打票模型 bootstrap 取 S0 → 带 S0 与 Cookie 重放判定。探测拿到响应头立即关闭，不读 SSE。错误最多重试一次，遵守 5 秒内的 Retry-After；仍失败的组合与 29 一样静置，但分开记录。候选之间默认间隔 50ms，探测最多 4 路并发，同一账号同时只有一个找票任务，单组合准备预算 35 秒。额度耗尽、限流冷却、停用、归档或无打票模型权限的账号不找票。

**票按模型分开、窗口共用**：打票模型的 S0 随找票得到。窗口内来了其他模型的请求而该模型没有票时，先拿票（不判定），之后照常判定。同组合同模型的拿票在进程内合并，并写入共享存储供 A/B 两槽复用。组合退役或换代后，所有模型的票一并作废。

**业务请求**：覆盖客户端自带的 state，固定发送该模型的票与配套 Cookie。21 完整交付；29 在任何输出前关闭响应，组合立即退役，满足安全条件时同账号换网关重放原请求：无工具或仅客户端工具、没有已交付内容。含上游工具（如 web_search）的请求不盲目重放。跨账号回退交给原有会话与安全续接规则。

**轮换**：窗口到期后准备下一组合；新组合验证通过后，所有尚未发送的请求切换过去，已发送的照常完成；旧组合最后一个在途请求结束后才开始静置。全部候选处于静置时交给原账号选择器尝试其他授权账号；无可用账号时明确报错，不会绕过静置或使用已停用的组合。

## 已验证事实

以下来自 2026-10-12 的真实实验，均以响应头信号为准。

- **保活**（测试账号 1，69 分钟，持续模式）：397 次请求中 29 共 29 次，切换 29 次；满血窗口 79–184 秒，中位数约 125 秒；找票中位数 3.3 秒。1h 静置后复测 24 个组合只有 1 个恢复，因此默认初始静置定为 2h。
- **换网关缓存**（测试账号 2，固定 session 与 `prompt_cache_key`）：7 次网关切换后的请求全部命中约 98.9%；追加对话 18 轮，除冷启动外全部命中。换网关不必然丢缓存。
- **同一张票双缓存**（测试账号 3）：同一 S0、同一网关交替发送两段不同前缀（各自 session 与 cache key），第二、三轮都命中 12,032 tokens。同一个 turn state 可以同时保留多份缓存。
- **跨模型**：Astra 的票上 6.1 Sol 返回 state（8/8，且不是回显原值），而夹在中间的 Astra 为 21；Sol 的票上 Astra 返回 state（3/3）。票必须按模型分开。
- **正常账号的 state 存活**（2026-10-13，PRO20，6.1 Sol，单网关）：同一个 state 在 0～10 分钟内重放 12 次，带路由 Cookie 与不带 Cookie 两条链全部不返回新 state，每个时间点的新 state 对照全是 21。窗口外继续使用旧 state 仍为 21，说明账号满血；重放后返回新 state 不是 state 过期。更长时间的重放见下一条结果。

## 轮转统计

插件 0.3.0 的顶层标签为“账号与网关 / 轮转明细 / 轮转统计”。界面仅展示窗口时长和简单冷却汇总。

- 轮转明细按账号、网关、批次、窗口起止、窗口时长和状态展示，可筛选和分页。每行“详情”展开验证时间、结束原因、检测结果及该代次的检测与访问记录；不展示其他耗时或多层业务小汇总。
- 有效窗口从该代次首次上游访问计至退役停止接新请求，进行中计至查询时刻。未验证可用的检测不形成有效窗口，时长显示未知，不填零。时间筛选只累计窗口与筛选范围的交集。
- 轮转统计展示各网关的窗口时长分布和每批窗口总时长，下方保留简洁的批次表。累计按代次去重，不把不同网关的窗口合计称为整轮自然跨度。
- 冷却汇总保留按实际再访问间隔分组的恢复比例柱图与样本数，同时显示已恢复次数、判定次数、总体恢复比例及恢复样本间隔中位数。比例为 21 / (21 + 29)，失败和待结果不参与，无判定样本留空。间隔按上次真实访问结束至再次访问开始计算，未知间隔不参与分组或中位数；不能据此推定上游准确恢复时刻。
- 账号卡片默认收起，展开后以紧凑标签和限高滚动区容纳约 100 个网关。点击单个网关只显示当前冷却和最近一次再访问结果。

页面查询不触发上游请求，持续模式、退避档位和失败后冷却翻倍规则保持不变。底层历史合同及已采集事实保留兼容，界面不再提供其他耗时指标。完整采集口径见 [设计说明](gateway-pool-usage-design.md)。

## 实现位置

| 组件 | 位置 |
| --- | --- |
| Rust 传输桥：路由、找票、拿票、额度准入 | `backend/crates/providers/openai/src/gateway_pool.rs` |
| 业务执行：固定票、交付前拦截、安全重放 | `provider/execution.rs` 中 `GatewayPoolAttempt` |
| 分组判定与 WS 拒绝 | `provider/mod.rs` |
| 持久化运行时 | `services/plugin_host/gateway_pool.py`（SQLite：设置、组合、租约、样本、切换、私有材料与各模型的票） |
| 策略（判定、退避、学习、窗口） | `plugins/gateway-pool/worker/policy.py` |
| 管理页 | `plugins/gateway-pool/ui/page/` |
| 授权实验入口 | Cargo 特性 `gateway-pool-experiment` 与 `tests/admin/gateway_pool.rs` 中带 `#[ignore]` 的测试，默认构建不含 |

Rust 网关经回环私有接口 `POST /api/plugin-platform/internal/gateway-pool` 调用控制面，使用独立的 64 位十六进制能力密钥（`gateway-pool-runtime.key`），不接受客户端 API Key。管理视图只返回组合状态、样本和已拿票的模型名，不返回 state、Cookie、账号 Token 或池服务凭证。

## 部署

```toml
[openai.gateway_pool]
runtime_url = "http://127.0.0.1:<控制面端口>/api/plugin-platform/internal/gateway-pool"
key_file = "<控制面根目录>/gateway-pool-runtime.key"
```

- `runtime_url` 必须指向当前活动的控制面槽；切换控制面槽时同步网关配置。端口以 VPS 实际状态为准。
- 能力密钥由控制面生成（0640），网关进程需能读取。
- 优先级、按 Key 的窗口和失败原因需要配套 Rust 选号桥、控制面队列能力及新版 UI；不能仅更新界面就启用实际排序。Rust 更新仍按 A/B 发布流程执行。
- 0.3.0 统计首次升级需要 Rust 计时采集、控制面的历史模块与 `gateway-pool.history.read` 能力同时具备。旧平台会拒绝缺少能力的新包，不能仅上传 UI 获得完整计时；UI 回退不删除历史。
- 状态库位于 `<控制面根目录>/gateway-pool-runtime/state.sqlite3`，备份时与能力密钥一起保留并限制访问。

## 验证

- Python：`python -m unittest discover -s services/plugin_host -p "test_*.py"`，覆盖持久化、A/B 合并、退避学习、完整流/收头区分、并发区间、两小时分段、批次与恢复、权限。`services/updater/test_static_plugins.py` 检查新增能力的包兼容性。
- Rust：`./scripts/build-local.ps1 -Task test -Package provider-openai -CargoArgs @('--features','gateway-pool-experiment','--test','main','admin::gateway_pool')`，mock 覆盖完整找票、错误重试、29 拦截与重放、工具副作用保护、额度耗尽、跨模型拿票。
- 前端：`node scripts/check-plugin.mjs gateway-pool`、`node scripts/build-plugin.mjs gateway-pool`、相关 lint 与 `pnpm --dir frontend typecheck`。
- 本机预览：构建主壳和插件后运行 `python -X utf8 scripts/preview-gateway-pool.py`，入口 `http://127.0.0.1:18335/extensions/gateway-pool`。使用真实主壳、插件包和统计库，账号与事件为模拟数据，无真实 Rust 网关或上游连接；每次启动新建隔离库。
