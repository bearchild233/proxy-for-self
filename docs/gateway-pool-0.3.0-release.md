# 网关池 0.3.0 与 API 密钥 0.3.3

日期：2026-10-13。本版包含网关池插件、API 密钥插件说明、Python 控制面和 Rust 选号逻辑的配套更新。

## 主要修改与优化

### 账号队列与参与开关

- “账号与网关”沿用账号管理的拖拽排序，所有 Key 共用一个持久化队列，在各自授权范围内从上到下使用。
- 账号完成一轮候选网关，或确认额度耗尽后，自动移到队尾；重复通知不会反复移动。
- 每个账号卡片右侧内置“参与网关池”开关。关闭后不再接新请求，已发送的请求正常完成，不改变账号的全局启停状态。
- 拖拽保存检查队列版本，避免覆盖其他操作或自动移尾产生的新顺序。卡片默认收起，展开后网关标签限高滚动，适配约 100 个网关的展示密度。

### 轮转明细与统计

- 页面分为“账号与网关 / 轮转明细 / 轮转统计”。检测记录并入轮转明细，支持账号、网关、批次等筛选和分页。
- 保留明细“详情”，可查看验证时间、结束原因、检测及访问记录。
- 时长展示统一为窗口时长，账号汇总使用图表，并保留每批窗口总时长与批次表。
- 未验证可用的组合不形成有效窗口；窗口按代次去重，时间筛选只累计与筛选范围重叠的部分。窗口总时长不等于整轮的自然时间跨度。

### 冷却汇总

- 保留冷却恢复比例图，按真实再访问间隔分组，同时展示恢复次数、判定次数、恢复比例和恢复样本间隔中位数。
- 恢复比例为 21 / (21 + 29)，检测失败和待结果不计入分母；无样本不显示为零恢复率。
- 间隔从上次真实访问结束计算到下一次访问开始，仅记录实际再次访问的结果，不推定精确恢复时刻。页面查询不主动请求上游。
- 持续找票模式、退避档位、失败后冷却翻倍及原有学习规则继续保留。

### Key 选号策略

- 保留“多个账号”与“多个分组”二选一。按请求冻结目录中的实际组成员身份分类，多个组中的同一账号去重，始终遵守 Key 授权范围。
- 授权范围内可用的降智组账号优先按网关池共用顺序使用；全部不可用时，普通账号按 Key 原有策略接手，未指定策略则继承全局设置。
- 只有最终选中的池账号使用网关池传输。关闭参与的池账号不会作为普通账号绕过开关；普通账号的严格续接和在途请求保持原有安全边界。
- 读取已有冷却状态即可排除暂不可用候选；控制面故障且已有可靠分类时允许普通账号回退，无法确认分类时保守报错。

## 数据与兼容要求

- 新增 SQLite 历史、批次、冷却样本与队列记录，以及 `gateway-pool.history.read`、`gateway-pool.queue.update` 能力；未修改冻结的 PostgreSQL 迁移。
- 历史记录与运行时租约隔离，队列进度独立于统计数据。界面回退不会删除已采集历史。
- 完整功能需要配套 Rust 网关、Python 控制面及两个插件。仅安装 UI 包不会获得真实选号和采集行为，旧控制面会拒绝不支持的新能力。
- 部署时先按既有 A/B 流程验证配套服务，再更新插件；备份控制面的状态库与能力密钥。Git 推送或 PR 本身不代表线上已经更新。

## 验证范围

- Rust 网关池 mock 测试覆盖混合账号与分组、队列优先、不可用回退、恢复、额度耗尽、控制面故障，以及严格续接和工具状态保护；凭据合同测试及相关 Clippy 检查通过。
- Python 测试覆盖历史采集、窗口与批次统计、冷却样本、队列持久化、自动移尾、并发版本冲突和能力授权。
- 两个插件完成类型检查、构建及组件包检查。本机预览使用模拟账号和事件，不等同于真实上游或生产验收。
- 需要真实上游凭据的忽略测试未执行。本版不包含普通组使用前自动检测降智、自动加入降智组的功能。
