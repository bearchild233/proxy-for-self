# 网关池插件

状态：开发分支 `feat/gateway-pool`，本机预览与 VPS 真实实验已完成，生产未启用。本文先说明术语和当前实现，再给出上线前剩余工作与验收步骤。

## 术语

| 术语 | 含义 |
| --- | --- |
| 网关 | OpenAI 上游的接入节点，名称形如 `unified-142`。同一账号经不同网关访问，可能得到不同质量的服务。 |
| 池服务 | 外部网关池服务（默认 `https://pool.0102400.xyz`）。`/gateways` 列出可用网关，`/cookie` 返回指定网关的 `__oailb` 与 `__cflb` 路由 Cookie。需单独的池服务 Bearer，与 OpenAI 凭据无关。 |
| 池成员标识 | 向池服务声明的账号身份：`gwpool-member:<上游账号 ID>/<上游用户 ID>`。只用于池服务限流与统计。 |
| 组合 | 一个“账号 × 网关”。检测、静置、学习和统计都以组合为单位，账号之间、网关之间互不影响。 |
| 票 / 找票 | 票指一套已验证的组合材料：S0 与配套 Cookie。找票就是为账号寻找一个判定为 21 的网关。 |
| S0 | 携带池 Cookie 第一次访问上游（bootstrap）时返回的 `x-codex-turn-state`。之后该组合的所有请求都固定带 S0 和同一套 Cookie，不使用上游后续返回的新 state。不同网关的 S0/Cookie 不能混用。 |
| bootstrap | 取 S0 的第一次上游请求，结果不做判定。 |
| 21 / 29 | 携带 S0 与 Cookie 重放后，在 HTTP 响应头位置判定：HTTP 200 且**不返回** `x-codex-turn-state` 为 21（满血，可用）；HTTP 200 且**返回**该字段为 29（降智，不可用）。只看字段是否出现，不比较取值。这是用户约定的实验信号，不代表已验证回答质量。 |
| 检测失败 | 401、402、429、超时、网络错误、缺少配套材料，或 `__oailb` JWT 的 `host` 显示实际网关与指定网关不同。记录真实状态码，不记为 29。 |
| 探测 | 找票用的请求：`gpt-6-astra`、reasoning low、输入 `hi`、无工具。拿到响应头立即关闭响应，不读 SSE 正文。 |
| 满血窗口 | 一个组合从首次实际发送起的可用时间，默认 180 秒。到期后开始找下一张票，旧组合继续服务，直到新组合验证通过。 |
| 静置 | 组合退役后禁止访问的冷却时间，从最后一次实际访问上游结束时起算。期间任何一次真实访问（包括探测）都会重新计时。 |
| 退避档 | 静置时长序列：初始档 → ×2 → … → 上限。复测仍为 29 或检测失败就升一档。 |
| 学习起点 | 同一组合连续两轮在同一档恢复，以后从该档开始静置；恢复档不同则清除学习值，回到初始档。只记最后一档，不累计各档时长。 |
| lazy / continuous | lazy（懒模式）：没有业务请求时不找票，窗口到期后由新请求触发准备。continuous（持续模式）：没有业务请求也按窗口轮换。 |

## 已验证事实

以下结论来自 2026-10-12 在 VPS 上的三次真实实验，全部以响应头 21/29 为准，没有读回答正文判断质量。

**保活实验（测试账号 1，69 分钟，持续模式，每 10 秒一次 `hi` 探测式业务请求）**

- 业务请求 397 次：21 共 368 次，29 共 29 次，HTTP 错误 0 次。共验证 30 个网关，切换 29 次。
- 满血窗口 79–184 秒，中位数约 125 秒，多数撑不到 180 秒。找票耗时 2.3–8.1 秒，中位数 3.3 秒。
- 1h 静置后有效复测 24 个组合，只有 1 个恢复，且恢复后约 133 秒又出现 29。其余升到 2h 档。2h 档恢复率尚未验证。
- 结束时池中 105 个组合全部处于静置。

**缓存实验（测试账号 2，读完整 SSE usage，session ID 与 `prompt_cache_key` 固定）**

- 固定输入约 12,168 tokens，6 个网关共 15 次请求：7 次网关切换（含回切）后的请求全部命中 12,032 tokens（98.9%）。有一次同网关重复请求命中为 0，原因未确定，当时为 21 信号。
- 追加对话模式（每轮追加新问题和上一轮真实回答），6 个网关各 3 轮，共 18 轮：输入从 12,227 增至 13,261 tokens，除首轮冷启动外全部命中，缓存量随对话增长。全部为 21。
- 结论：换网关不必然丢缓存；同一组合固定 S0 可以连续服务多轮追加对话。命中仍可能偶发波动。

**连接**：部分账号绑定的代理能连 ChatGPT，但连池服务会 TLS 失败（`WRONG_VERSION_NUMBER`）。实验中池服务请求改为 VPS 直连，探测与业务请求仍走账号代理。

## 当前实现

| 组件 | 位置 | 职责 |
| --- | --- | --- |
| Rust 传输桥 | `backend/crates/providers/openai/src/gateway_pool.rs` | 判断请求是否启用、找票、准备材料、组合租约、额度准入 |
| 业务执行 | `provider/execution.rs` 中 `GatewayPoolAttempt` | 固定 S0/Cookie；21 完整交付；29 在交付前关闭并同账号换网关重放 |
| 探测传输 | `transport/probe.rs` | 头后立即断开；可选读完整 SSE usage（仅实验特性） |
| 持久化运行时 | `services/plugin_host/gateway_pool.py` | SQLite 保存设置、组合、租约、样本、切换、私有材料 |
| 策略 | `plugins/gateway-pool/worker/policy.py` | 判定、退避、学习、窗口，可随插件包热更新 |
| 管理页 | `plugins/gateway-pool/ui/page/GatewayPoolPage.vue` | 设置、组合状态、检测样本、切换记录 |
| 实验入口 | Cargo 特性 `gateway-pool-experiment`、`tests/admin/gateway_pool.rs` 中带 `#[ignore]` 的真实测试 | 默认构建不含，仅用于授权实验 |

数据流：Rust 网关通过回环私有接口 `POST /api/plugin-platform/internal/gateway-pool` 调用控制面，使用独立的 64 位十六进制能力密钥（`gateway-pool-runtime.key`），不接受客户端 API Key。S0 与 Cookie 存在 `<platform-root>/gateway-pool-runtime/state.sqlite3` 的私有表中，A/B 两个网关进程共享，管理视图不返回材料、账号 Token 或池服务凭证。

业务规则：

- 只在选定分组内对 OAuth 账号生效。额度耗尽、限流冷却、停用、归档或无 Astra 权限的账号不找票。
- 窗口到期后，尚未发送的请求改用新组合，已发送的继续在旧组合完成。29 立即退役组合。
- 29 重放只限无工具或仅客户端工具的请求；含上游工具（如 web_search）的请求不盲目重放。已交付的输出不撤回。
- 探测错误最多重试一次，遵守 5 秒以内的 Retry-After；仍失败的组合与 29 一样静置，但单独记录。
- 候选之间间隔默认 50ms；探测最多 4 路并发，单账号同一时间只有一个找票任务；单组合准备预算 35 秒。

## 已确认的第一版范围

- **只有 HTTP Responses 的 `gpt-6-astra` 请求经过网关池。** 原生 WS、其他模型、非 OAuth 账号即使在选定分组内，也走原有调度，不报错。当前代码对这些请求返回 Unsupported，需要修改。
- **默认初始静置改为 2h**（上限 24h），默认 lazy 模式。两项都可在插件设置中修改。

## 上线前剩余工作

### 1. 功能调整

1. `provider/mod.rs`：WS、非 Astra、非 OAuth 请求改为绕过网关池，按原流程调度。同一会话中 HTTP 请求带 S0、WS 请求不带，需补测试确认会话捕获（`session_capture`）不会把 S0 写进普通会话状态。
2. `policy.py` 与管理页：`initialRestSeconds` 默认 7200。已有设置不覆盖。
3. 池成员标识：默认由账号的上游账号 ID 与用户 ID 自动生成 `gwpool-member:<account>/<user>`，管理页映射改为可选覆盖。当前只支持手工映射，实验用的就是自动生成的格式。
4. 池服务出口：增加设置项“池服务请求使用 VPS 直连”（默认关闭）。开启后只有 `/gateways` 与 `/cookie` 直连，探测、业务和额度请求仍走账号出口。
5. 池服务错误码：`rate_limited`、`consumer_rejected`、`consumer_rate_limited` 等表示池服务侧的限制，按池服务整体退让，不让组合静置、不升档。`no_gateway`、`all_cooling`、`no_live_pair` 只结束本轮找票。
6. 后台候选账号：目前按手工映射的账号扫描。改为按选定分组的实时成员扫描，账号移出分组后不再找票。

### 2. 正确性收尾

已知、需要修复并补测试的问题：

- 设置修改后，已不在候选列表内的就绪组合不会自动退役。
- 插件停用时，就绪组合只减少在途计数，不退役；重新启用后可能直接复用过期材料。
- 控制面私有接口不可用时，选定分组应失败关闭，其他分组不受影响（需补测试证明）。
- 切换记录尚不能按账号、网关筛选；没有聚合统计或导出（原始样本已保存）。
- SQLite 未启用 WAL，每次管理视图读取都开写事务；结果上报不是显式幂等。
- 响应头中 state 值含非 ASCII 字节时，可能误判为 21。
- 两个控制面进程同时首次初始化时，能力密钥文件存在创建竞争。

### 3. 部署前提

- 网关配置中的 `openai.gateway_pool.runtime_url` 必须指向当前活动的控制面。控制面也有 A/B 两槽（18335/18337），两份部署文档对当前活动槽的记载不一致，部署时按 VPS 实际状态确认。切换控制面槽时，网关配置要同步，或改为一个稳定的回环入口。
- 能力密钥文件要能被网关进程读取（0640，组权限）。
- 首次启用需要同时升级 Rust 内核（A/B 发布）和控制面 `server.py`；之后 UI 与策略可以单独热更新。

## 验收步骤

### 本机

- Python：`python -m unittest discover -s services/plugin_host -p "test_*.py"`、`python -m unittest discover -s services/updater`。
- Rust：`./scripts/build-local.ps1 -Task clippy -Package provider-openai -CargoArgs @('--all-targets','--','-D','warnings')`，以及 `-Task test` 运行网关池集成测试。
- 前端：`node scripts/check-plugin.mjs gateway-pool`、`node scripts/build-plugin.mjs gateway-pool`、相关 lint 与 typecheck。

### VPS 独立测试环境

独立端口、独立数据库、独立控制面根目录，不连接生产数据库，不改生产入口。

1. 部署新内核与控制面到测试端口，安装网关池插件。
2. 导入 1–2 个测试账号，只导入 Access Token，不导入 Refresh Token，避免与生产续期竞争。保留账号原出口。
3. 用真实 Codex CLI 以 HTTP 方式连接测试入口，选定测试分组，验收：
   - 找票、21 业务完整交付，窗口到期后无感切换，切换记录正确；
   - 多轮对话与工具调用在切换前后连续，缓存命中与实验一致；
   - 遇到 29 时客户端不收到降智回答，重放后正常完成；
   - WS 请求和其他模型绕过网关池，行为与原系统一致；
   - 重启控制面、重启网关后静置与学习记录不丢失；
   - 管理页展示与统计正确，不出现凭据。
4. 结果交给用户确认，之后才进入生产。
